# 实用内容编写契约

适用于新城市与正文修订。先读已有需求、已批准路线和当前内容；沿用真实旅行条件，不为写文章擅自新增必去点或改变日期。它补充 content-and-functions.md，内容是否成立由章节职责与试读答案判断，不按篇幅评分。

## 从读者的问题组织内容

先分清读者在这一章是认识地方、挑选体验，还是执行行程，再组织内容。实用也包括理解一座城市、分辨街区、读懂眼前事物，不要求每段都给一个命令或删减方案。相同信息只在最合适的位置完整解释，其他位置短提示或链接。

默认阅读顺序是「认识目的地 → 区域与当地生活 → 每日行程 → 餐饮、文化、购物与现场工具」。先让读者知道这个地方是什么样，再解释去哪里、怎样走。熟悉目的地的人可直接从目录进入行程；不要让正文每章都从“第几天”讲起。

城市介绍讲地理、形成过程、生活风貌与季节；街区章深入区域差异；行程章才把这些地方排成天。总路线图和逐日总览放行程章。城市介绍与住宿正文应能独立于当前六天或八天安排成立，不能按日次给城市下定义。

每个小节至少增加一项有用理解、具体观察或可执行信息。按内容需要组合以下要素，不机械地为所有段落套同一模板：

1. **判断**：谁适合、谁可以跳过；选 A 而非 B 的具体条件。
2. **依据**：这一判断由什么当地事实支持；背景知识应解释眼前能看到的东西。
3. **做法**：确切区域、场所或入口，先做什么再做什么，需要准备什么。
4. **代价**：占用哪段时间、预算或体力，哪些行程需要缩短；估算明确标注。
5. **限制与退路**：闭馆、排队、缺票、天气或不合预算时，改什么、保住什么。

介绍性段落可从一个当地事实展开，解释它如何形成今天可见的街道、建筑、食物或生活方式；操作段落先交代情况再给步骤。长内容按主题拆段，避免整段提醒与固定的“结论、做法、风险”三段式。背景必须具体，操作必须能照做，两者不互相代替。

## 章节的责任

| 章节 | 读者应获得的理解或能完成的事 | 写到能使用的程度 |
|---|---|---|
| 认识目的地 | 这是什么样的地方，地理与历史如何影响今天，住哪种区域更适合自己 | 先讲目的地本身，用具体环境与生活细节建立认识。住宿比较区域位置、街道环境、生活配套、交通连接和代价，不以“第2天/第5天在这里”作为主要理由；机场关联有助判断时保留。天数分配、删站和航班倒推放行程/交通章。 |
| 区域与当地生活 | 几个街区为何不同，各自值得看什么，怎样按兴趣挑选 | 具体到区域内不同街道、空间、文化活动或产业。背景与现场可见细节相连；片区之间说明空间关系。图片后的正文必须实际渲染，不能只显示体验摘要。全章不复述“上午A、下午B”；只留一条到相关日程的链接。 |
| 餐饮 | 什么值得专程去、当地有什么特色、日常与休息时在哪吃 | 默认四类推荐：值得专程吃、当地特色、日常连锁、咖啡与甜品。一店一主分类，给准确分店、真实菜品、预算口径与营业条件；不为分类凑品牌，市场按区域介绍。当日候选须适合实际区域和用餐窗口。 |
| 文化与参观 | 选哪种文化体验，进场后看什么，是否值得占用半天 | 场所性质与关键背景、具体观看线索、建议观看顺序、建议时长、门票/预约与营业条件。先介绍内容，再将与日程有关的替换说明放短注或链接；不逐条用“第几天”开场。 |
| 购物与伴手礼 | 为某个用途去哪买，候选之间有什么区别，如何判断值不值得买 | 按用户目的组织，连接具体店铺/分店/街区及行程日；给品类专属判断依据（例如笔芯兼容、纸张用途、二手配件、食物保存），再写携带与预算取舍。库存与限定信息不保证；不每条重复“看尺寸、看包装”。 |
| 交通与实用贴士 | 遇到具体情况时下一步怎么做 | 使用「情境 → 操作步骤 → 容易错的边界 → 失败后的处理」。覆盖本旅程实际需要的机场转场、市内票券、付款、行李、网络、预约与求助。比较交通票要说明运营商范围、适用路线与何时不值得，不只列产品名。 |
| 行前准备 | 现在需要处理什么，做到哪里才算完成 | 按提前办理、临近出发、当天出门等三个行动阶段组织，给具体操作、入口、完成条件和适用范围。国籍、证件与行程条件未知时先给核对任务，不能默认签证资格；勾选不代表官方确认。 |
| 语言卡 | 在当前场景怎样表达，对方可能怎样回答 | 按实际场景组织，每组约4–5句并配高频词；准确中文与目的地表达对应，非英语目的地补备用英语，读音与用法按需展开，常见回答在同场景查看。能直接出示、能听懂常见回应，不用生硬直译或重复问候凑数。 |

文化参观要给读者理解现场的线索；购物要讲选择；贴士要讲步骤。不能把三个章节都写成“不排队、注意时间、看官网”的提醒集。

餐饮先解释当地菜式、食材、口味和点法，再给具体餐厅；“看懂菜单”不能变成“去哪天吃/排队太长就换”的提醒。地点详情的介绍先说这个地点是什么，导航、营业条件与行程备注另有位置。

## 先建立目的地画像，再决定篇幅

这套方法适用于所有目的地，东京只是案例。写作前找出最影响本次旅行的当地条件，按影响程度、发生频率与路线相关性排序：地形和距离、气候与季节、交通可达性、文化与宗教场所性质、消费与基础服务。每个重点应带来对当地的具体理解，或帮助一个实际选择；背景介绍不必以行程操作收尾，但不能只列特色名称。当地重要的不利条件也要研究，如季节性空气质量、洪水或访客准入；只写一般晴雨、遮肩脱鞋，不能代替具体影响。

- 轨道交通密集的城市，重点解释片区与运营商；海岛重点解释码头、渡船取消与返程余量；山地和自然目的地重点解释季节开放、日照、地形与必要许可；分散城镇重点解释住宿基地、车辆和最后一段交通。当地不适合买通票，就减少票券篇幅，不沿用东京比重。
- 文化内容先分清活跃宗教场所、社区空间、遗址与博物馆，再写游客能进入哪里、参与或观看什么、限制怎样影响当天。衣着、仪式、摄影或访客准入按具体场所核实，国家或宗教标签不能代替查证。
- 消费内容按当地实际品类、付款习惯、服务费、议价场景与携带条件组织，不默认购物等于百货、角色商品和退税。无购物需求时仍保留必要消费信息，兴趣篇幅转给当地更有价值的体验。
- 气候、地形或服务稀疏若影响用餐、补水、休息、信号与返程，就写进出发准备、时间轴和备选；不只在城市介绍里提一句天气或距离。

在 `editorial-review.md` 记录本目的地的 2–3 个主导条件及其导致的路线、住宿、时间或章节取舍。保留产品内容域，内部顺序、深度和条目数量随需求调整。

## 事实与核实

- 查经营方、交通运营商、场馆、政府及官方旅游机构。地图只用于位置，不证明营业、价格与预约。
- 时刻、价格、规则等会变的信息，要给最近可核实的实际内容、适用条件、核查日期与就近来源。**“以官网为准”只可作为补充，不能替代查证。**
- 区分核查日、规则生效日和旅行日。尤其签证、免税、票务：新旧政策并列时明确哪一条已生效；出行日期未知不把未来规则当成已适用。
- 未能确认的必要信息，写清缺什么、在哪个入口查、输入/比较什么，以及这会影响哪一步。不得编造票价、出口、换乘次数、无障碍条件、库存或具体店铺。
- 编辑建议与事实分开：停留时长、排队上限、预算分配属于建议，不是场馆承诺。建议本身也要符合当天剩余时间。
- 来源贴在相关条目末尾，可折叠汇总但不可只有全书末尾一堆不明缩写链接。来源的内容要真正支持邻近主张。

## 营业与日历先于路线

所有目的地按 [营业与日历核对](opening-and-calendar.md) 先研究当地节律，再排真实日期或条件路线。店休、最晚入场、分段营业、宗教及季节限制要进入时间轴与备选判断，不能只写一句出门前确认；不要把东京样例当其他城市惯例。

## 防止把提纲当正文

### 开篇专项：认识地方，不是认路线

`openingLead`、`intro`、`portraitLead` 与 `portrait` 一起检查。封面导语可以短，认识章节必须展开：这里怎样形成今天的面貌；这些背景在街道、建筑、饮食或生活里怎样看得到；地理和季节如何影响体验。不能只交代方位后立刻转入分天、坐车、下山、回酒店。先完成目的地介绍，再让住宿与路线承担操作信息。

反例：“素贴山在西边，宁曼接在下山后，河东另排一天。”这是行程组织，即使信息正确、字段齐全，也不回答清迈是什么样。采编应先查当地历史文化与当代生活的关联，例如兰纳背景如何体现在寺院、古城为何保留当前空间形态、旧城与新街区各有什么日常生活；查清再写具体解释。这里列的是研究问题，不是未经查证可复制的清迈事实，也不是各城市一律要写寺庙的模板。

同理，区域标题应指向该区域真实主题，不批量填“先认环境／再决定停留方式”；抵达和返程是行程任务，不替代真实区域。自审时遮住天数、日次与交通句，再读剩下的内容：若只剩地名和泛泛的礼仪，必须回到研究与写作，不靠追加一段停留建议修补。`portrait` 的试读问题必须同时覆盖形成背景、当下生活与现场可见线索，答案应摘录相应解释；只问“怎样分区走”不算通过开篇审阅。

**默认写到能读懂，而不是刚好通过构建。** 城市介绍先展开几个当地主题，通常包含地理格局、形成背景与生活文化；区域正文解释各自的性格、现场能看见的细节和游览取舍。一个标题下只有“去哪里＋注意什么”仍是提纲，分成两条也没有增加深度。以两三个衔接的短段讲清一个重要主题，比增加更多空标题有效；小主题可以短写，不机械统一长度。餐饮、文化和购物须解释对象本身与选择依据，不能都写成候车、包装、看官网等提醒。

先写正文，再为每个区域写一句提炼后的导语与一项不同角度的体验；不要从每日行程逐站反推同名区域。返程、机场转场是交通任务，不独立充当地方文化专题。住宿按区域生活环境与连接条件比较，“前两晚／后两晚”的安排只作为行程关联。旅行模式压缩的是阅读路径，不是地点的基本介绍：先说它是什么、到场看什么，再给当日限制和交通；抵达、离开和天气备选必须按当天场景写，不能直接复用所有地点的通用提醒。

新城市先完成城市画像、区域正文与专题选择，再进入大图排版。城市应建立地理、形成过程和生活风貌的认识；区域的导语、正文与体验旁栏各有新增信息；文化、购物、餐饮不能各剩一条通用提醒。不同目的地深度由主题决定，不固定套用东京篇数。

用 `audit_editorial_depth.py` 辅助定位异常，再在最终页面试读。若把地名换掉仍能原样用，或删去图片后只剩导航与注意事项，需补研究和介绍，不能靠缩小图片、凑字数、重复安全提醒提高密度。`editorial-review.md` 必须记录页面能回答的问题和未完成项；浏览器或语言分支测试通过不代表新目的地的内容验收通过。

## 写作流程

新城市先执行 [采编工作流](editorial-workflow.md)：研究地方 → 独立城市介绍 → 区域与专题 → 路线与旅行模式 → 固定职责试读。以下步骤不能反向从已有行程提炼所谓城市背景。

信息密度是新增理解与有效选择的密度，不是页面上文字的占比。大图继续保留；相邻正文应回答一个完整问题。删掉所有地名后仍能通用于任意城市、同一提醒出现多次、只有“注意／确认”而没有确认对象和结果的段落，都应重新采编。遇到资料不足，优先更换有依据的候选或明确缺项，不用通用安全提醒填补。篇幅可以不均匀：用户最关心、当地最有差异、选错代价最高的主题先展开，其他内容短写。

制作分两次判断：排版前先确认背景、比较和操作答案已经写出来；最终页面再检查这些答案是否实际可见、查得到。城市与区域正文不从照片说明或每日 lead 自动扩写，旅行模式也不把整篇文章复制进去：它引用地点介绍，补当日条件，长背景留在正文。两次判断沿用同一份试读记录，不增加平行清单。

1. **问题清单**：先写本次读者最需要回答的问题，按章节职责归属。优先解决高频或选错代价大的问题，再补兴趣内容。
2. **查证笔记**：记录事实、来源、核查日期、生效日期（若适用）与尚未确定的条件。
3. **按章节职责写作**：城市和区域解释地方，专题解释对象与选择，行程和贴士解释操作。每条增加新的信息，不把同一条路线换几种说法。
4. **核对关联，不把关联铺满正文**：检查推荐地点与主线/备选身份、日程是否可行，把跨章连接做成短注或链接。核对路线是编辑工作，不等于所有章节都要写日次。
5. **场景试读**：只用页面回答下面的任务，答不出就回到对应条目补写；不能以字数已达标或来源数量够了放行。

## 验收：用页面完成任务

在工作台留一份 `editorial-review.md`，记录问题、答案所在位置、仍缺的信息和实际复核结果。不是读者页面里的制作日志。

试读记录按本次修改涉及的章节写「固定读者问题 → 页面位置 → 实际答案及支撑它的正文完整段落 → 缺项」，证据格式统一见 release-verification.md。例如城市章要能摘出当地背景的解释，不能用“能找到201路”证明城市介绍合格；文化章要能说出实际观看内容，不能只记录“已给营业链接”。旅行模式按本次范围逐日记录逐站介绍、当天提醒与备选的实际答案；完整新刊覆盖每一天，局部修订覆盖受影响日。仅写“已检查、可查、通过”不算实质试读；无法给出答案时应补研究，不得以浏览器测试通过交付。既有数据完整性校验不负责判定这些文字是否有用，执行者仍须完成此项判断。

- **住宿**：读者给出机场或游览偏好后，能选出一个优先住宿区，并说明另一个区的取舍吗？
- **地域与时间**：能理解几大片区的关系，知道为什么这样分天、少半天删哪段吗？
- **参观**：只选一间馆时，能比较两种体验、选择其一，并说出到场看什么、预留多久和需要先做什么吗？
- **用餐**：读者能分清值得专程吃、当地特色、日常连锁与咖啡甜品，并根据当前所在区域和用餐时间选到准确分店吗？菜单、费用与营业条件是否支持这个选择，而不只是店名和品牌首页？
- **购物**：给定具体用途和行程日，能定位候选，知道两个选择的区别、现场检查什么和何时不买吗？
- **交通票**：能判断这趟路线是否覆盖、怎么买/怎么用、不覆盖的部分如何处理吗？
- **突发情况**：没票、闭馆、丢物、断网或赶不上末班时，有明确下一步而不是只写“注意安全”吗？
- **准备**：给定一个任务，能知道现在是否适用、去哪里操作、怎样算完成吗？三阶段顺序是否符合真实办理时间，而非把旧打包清单拆成三栏？未知国籍或日期是否保留了必要条件？
- **语言**：含会话的场景能找到可直接出示的一句话，纯词汇场景能找到对应标识或地名，理解适用条件与常见回答吗？读音与辅助说明是否可展开，表达是否自然、准确地对应中文含义？
- **手机查找**：通过章节内导航找到答案后，能直接读到关键条件与来源，长段落没有挤成难读的文字墙吗？
- **旅行模式**：不打开杂志正文，能看懂每站的内容、走法、营业限制和下一段交通，找到当天用餐候选，并查阅完整语言锦囊吗？购买建议是否对应当天区域与需要；备选是否讲清触发、替换段、时间、走法及确认条件？往返查询后是否仍是原日期、原位置？若关键事实只在长文里出现，须补入随身阅读的位置并保持一致。

旅行模式还要按时间从头走读当天：相邻站点的交通说明是否真对应这一段（出发点、到达点、方式及预计耗时），跨餐时是否有当地可行的正餐窗口与候选，而非只出现咖啡甜品。到达、停留、用餐和下一次出发要接得上；不能把“字段都有”当成行程成立。
- **当地适用性**：是否针对主导条件改变了实际决策？只换地名仍能原样成立的段落，应补当地依据或删去；是否把篇幅留给本次重要选择，而非每城固定配额的博物馆、购物和地铁条目？
- **脱离日程也能读懂吗**：遮住日程和“第几天”，城市介绍、住宿及区域章是否仍然准确、具体、有价值？区域正文与体验摘要是否互相重复？目录和正文顺序是否从认识到深入，再到执行？
- **编辑语言**：按 [旅行编辑语言](travel-editorial-voice.md) 通读全书，检查套话、重复提醒和机械句式；不能靠替换几个词或删除必要条件冒充去AI味。

每个实际适用的问题都要能从页面回答；不适用则说明本次原因。程序只检查字段、来源引用与渲染完整性，不能替代这些人工判断。

## 不合格写法与改法

- “住宿先看交通” → 比较本路线相关住宿区，写对哪个机场/游览方向更方便、站内步行或换乘的代价，以及酒店地址未定时怎样验证。
- “博物馆留两小时，票务看官网” → 指定体验重点、初访观看顺序、常设与特展票区别、当天闭馆条件，再标建议时长和官方入口。
- “文具看尺寸，易碎品包装好” → 说明具体店铺适合哪类纸笔，如何核对纸张用途、替芯或笔尖；关联当天区域，并区别自用与礼物。
- “地铁换乘复杂，预留时间” → 说明用线路名、方向终点、站号和出口确认路线，运营商换乘对通票的影响，带行李时怎样选择电梯路径。

例子是编写方法，不是东京事实模板；新城市须重新研究，不能只替换地名。
