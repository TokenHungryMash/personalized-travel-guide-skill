# 跨目的地适配

默认 `create_workbench.py` 复制 `assets/destination-reference/` 的当前引擎及巴厘岛旧示例。复制不是内容适配；旧示例的区域正文、来源绑定和大图仍须按现行要求补全或替换，不能承诺未经编写即可通过构建。`--sample` 才复制可还原的冻结福冈样刊，仅用于还原或只读比较。两套都不是已完成的新目的地手册。

## 新工程的文件

先读 [字段约定](authoring-contract.md)。新工作台提供 `content.schema.json` 等本地 schema、`authoring-examples.jsonc` 和待填写的 `directory-plan.json`；不要凭自然语言习惯推断 day 的索引或跨文件匹配关系。

- `edition.json`：城市、国家、天数、语言、币种、封面、导语和身份信息。创建脚本已隔离存储键，已有手册修改必须保留原键。
- `content.json`：地点、旅行日、日程与交通、区域、来源。保留稳定地点 ID，来源与区域不要冒用旧目的地信息。
- `editorial-content.json`：城市介绍、住宿分区、体验、餐厅分类、文化、购物、实用贴士、清单、语言卡和来源显示名。类别、数量与排序服从目的地，不照抄示例名单。
- `edition-renderer.py` / `build.py`：章节顺序、目录、图文与打包。按 ID 管理章节，当前位置从真实标题读取。
- `place-photos.json` / `edition-photos.json` / `media/`：地点识别图与正文大图。`role: thumbnail` 只适合小图。缺图时保留资料，使用文字卡，不显示“地点照片”占位框。
- `app.js`：旅行模式与同页面共用的本机状态。导航查询、基础币种与语言主要取自 edition 和地点数据；新目的地仍须核对地点 query、自由安排地点 ID、地图服务及界面上的服务名称，不能假定全部逻辑已参数化。其他国家的导航服务按可用性选择，不把韩国导航、印尼币种或任意城市名设成全球规则。汇率工具当前换算到 CNY，是面向中文读者的显示约定；改变结算需求时单独适配，不能把它描述为任意目标币种换算。
- `maps.json`、`verified-coordinates.json`、`maps/`、`map-ui.js`：使用新目的地真实底图与核实点位，检查每日路线、总览、标签与投影。实际转场时间另核实。
- 字体、样式、日程计算、账目模型可以复用；不要把字体内部别名当城市内容批量替换。

## 结构判断

城市旅行按街区组织，海岛按海岸/聚落组织，多城市按城市再细分区域。特色体验可来自文化、自然、餐饮、购物、运动、夜生活等；先判断读者兴趣与当地代表性，再安排时间。区域内的走法须真的在该区域，跨区线路只放在每日行程。每个候选说明主线、替代或补充角色，避免地图与区域段落暗示所有候选都在一天走完。

体验、每日行程、区域指南与地点库引用同一组地点，不复制出冲突的地址、时间或图片。餐厅按实际选择维度分类，每类可有多家，默认仅店名与位置/菜式摘要，展开看详情。图库覆盖不足时优先正确，再考虑完整，禁止错误分店图和空图框。

## 构建与检查

工作副本内先运行 `python -m pip install -r requirements.txt`（Pillow、fonttools[woff]、jsonschema），再运行 `python -X utf8 build.py --preview`，得到开发页及自包含 HTML。新增文字后按需运行 `font_supplement.py` 再构建。Node 检查使用本工程 `package.json`，安装依赖后运行 `npm run check`；或设置 `JOURNAL_CHECK_MODULES` 指向已有依赖并执行 `node check-edition.cjs .`。参数是工作台目录，不是 HTML 路径。

新建副本清除模板的开发页、单文件成品、构建报告和可选餐厅图片研究账本；内容 JSON 与素材仍为待适配示例。交付前运行 `audit_destination.py` 与 `audit_maps.py`，检查旧城市、国家、语言、币种、固定天数、地点 ID、地图范围和来源。检查全部地点的图片文件与角色、无图布局、两处目录与正文顺序、日期切换与笔记/账目保存。实际浏览器查看桌面与手机的区域专题、带图/无图地点卡、行程和旅行模式。数据一致性检查通过不代表目的地事实已经核实。

参考图片保留原始署名与出处，图片不因此获得代码许可证的授权；对外发布时按具体素材许可处理。用户笔记、账目、附件和浏览器存储不写回技能包。
# 当前制作补充

新旅程首先遵守 [问卷流程](intake-workflow.md)。地点库按 [城市性质与停留长度](directory-standard.md) 规划规模，照片不能把区域默认图当具体场馆图。每日摄影按 [旅行工具规范](travel-tools.md) 编写具体地点建议，设备未知不沿用旧样刊相机型号。预算读取本期 `edition.json`，记账按 [多币种契约](ledger-contract.md) 验收。


摄影叠印、动态导航、底部日期、头像及当天备选必须随新工程保留，模块顺序统一以 [当前引擎契约](current-engine.md) 为准。新增完整旅行日同时编写 alternatives、shopping 与 photoPlan，不允许沿用前一城市的备选路线或购买建议。对正文和旅行模式分别检查当地条件，不能只更换章节文章。
