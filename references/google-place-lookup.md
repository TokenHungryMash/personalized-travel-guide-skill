# Google place lookup: one source of truth

This protocol owns Google identity/rating lookup in all editions. A missing rating is acceptable; silently skipping the initial lookup is not. It overrides older “opportunistic only” shorthand and duplicated retry prose.

The first exact-place lookup is the run-level capability probe. For an access failure, retry that same venue once; stop after two different venues fail to open consecutively after retries. Any successfully opened venue resets this consecutive-failure count.

1. During the original research batch, open an exact Google Maps result for every selected sight and restaurant, including chain branches. Match name and address. This is the normal identity lookup, not an additional ratings project. Capture the visible score, review count when available, exact place URL and retrieval date together. Do not substitute search snippets, another branch or another platform's score.
2. Allow one bounded loading interval and reread the same panel once if needed. If the panel opens but no attributable score is shown, record `no_visible_rating` and continue with the place. Do not search repeatedly for a missing number. A parser failure alone does not establish that Google is inaccessible; use the authorized visible panel where available.
3. For a transient loading/access failure only, try that place once with a shorter exact query. An explicit URL/security denial stops that denied access method immediately: do not retry with rewritten URLs or another transport to bypass it. Record the denial and use an accessible exact official venue/address source; omit unavailable Google ratings. After two different places consecutively fail to open after those attempts, stop further Google requests for that run. A successful panel resets this count. Respect an explicit security denial immediately; do not bypass it. A local handbook-page limitation does not establish that public Google Maps is blocked.
4. Save one compact `research/google-lookup.json` batch ledger. Each attempted row contains `place_id`, `query_url`, `checked_at`, `status` (`verified`, `no_visible_rating`, `access_failed`, or `identity_unresolved`) and a short factual `note`. Verified ratings also live in the source place record. Unattempted places are `not_attempted`, or `skipped_after_access_stop` with a reference to the actual two-place failure evidence. Never report either state as “查不到”. This ledger replaces extra per-place reports/timers.
5. Before compiling a new build, reconcile selected sight/restaurant IDs with the ledger. Resolve accidental `not_attempted` rows in the same bounded batch, not a second broad search. Do not repeat successful checks just to refresh ratings. Keep public card scores omitted when unavailable; do not display internal status clutter.


Raw HTTP 200 JavaScript shells are not place panels and must not be recorded as `no_visible_rating`. Use an authorized rendered panel if available, otherwise record the actual access/rendering limitation and apply the existing stop rule. See [fetch recovery](fetch-recovery.md).
