# 模板使用与实际验收

## 先选择正确入口

| 任务 | 使用方式 |
|---|---|
| 新城市或新旅程 | `python scripts/create_workbench.py <新工作目录> --project-id <唯一标识>`，复制 `assets/destination-reference/` 当前引擎。巴厘岛旧示例仍需重新编写与换图，状态为 `reference-needs-authoring`。 |
| 修订已有手册 | 在已有工作台修订，保留其存储键与备份身份；按需要同步当前引擎，不能重新建键让旧记录不可见。 |
| 原样还原福冈认可样刊 | 上述命令加 `--sample`，复制冻结 `assets/fukuoka-reference/`。仅恢复样刊，不以它覆盖当前引擎，也不把样刊旧事实当新旅程资料。 |

所有新目录须位于技能包外，且不存在或为空；创建脚本拒绝覆盖非空目录。冻结资产始终只读，个人内容写工作副本。新工程的字段和文件归属见 [跨目的地适配](destination-adaptation.md) 与 [编写约定](authoring-contract.md)，模块及加载顺序唯一口径见 [当前引擎契约](current-engine.md)。

已有手册升级引擎时，先记录原 `app.js` 的 KEY、edition.slug/backupFormat 与 magazine-workbench.storage_key，只复制本次需要的引擎文件。模板 app.js 的 KEY 是参考城市常量，不能原样覆盖：复制后恢复原 KEY，并核对与原 IndexedDB/备份身份的关系；不要为了让测试找到数据而重新建键。新工作台由 create_workbench.py 自动替换，旧工作台复制文件不会自动执行此步骤。升级前后用同一浏览器记录验证笔记与附件仍可见。

同时保留该手册的 `fonts/`、`body-font.css`、`serif-font.css` 和 `font-supplement.css`，不以模板字体子集覆盖本期已经补齐的汉字。需要更新字体规则时先保留双方有效子集再合并；新正文构建后审计最终内嵌字体覆盖，缺字才补齐并重建。浏览器本机字体回退可能掩盖缺字，截图能显示汉字不代表离线内嵌字体完整。

## 默认新工作台的构建

先按实用内容契约写可回答读者问题的正文，再配置照片与构建。`build.py --preview` 生成待验收预览；试读正文与所有日期的旅行模式，完成绑定当前内容的 `editorial-review.json` 后，再执行 `build.py` 生成正式版。正式构建通过后仍须核对最终文件身份与受影响的浏览器检查，不能把数据检查通过等同于内容或交互质量已经确认。历史示例和最低量不是默认写作深度，不按“写到错误消失”为目标制作。

先完成目的地正文、`area_sections`、来源、逐日 `photoPlan` / `shopping` / `alternatives`、地点库计划、地图与配图。创建脚本启用现行正文和证据校验，默认巴厘岛旧示例不保证直接通过；修复或替换待编写内容，不关闭质量检查来获得成品。地点数量遵守 [地点库标准](directory-standard.md)，旅行工具遵守 [旅行工具规范](travel-tools.md)。

Python 3.10+；在工作台按需安装 `requirements.txt`。文字初稿完成后先运行 `python -X utf8 build.py --check --preview`；修正结构与内容缺项，再完成素材并运行 `python -X utf8 build.py --preview` 试读。新增中文有缺字时运行 `font_supplement.py` 再重建。当前交付文件名由渲染器按本期城市和旅行天数生成，以 `build-manifest.json.artifact` 为准，不猜文件名。开发页 `index.html` 仍引用工作台资产；交付使用清单中的自包含 HTML。

Node 依赖使用工作台 `package.json`；`npm run check` 或 `node check-edition.cjs <工作台>` 检查模型、模拟 DOM 与样式，不等于真实浏览器验收。需要共享依赖时设置 `JOURNAL_CHECK_MODULES`。全部交付检查、参数及范围统一见 [构建身份及交付验收](release-verification.md)。

## 冻结福冈样刊：仅用于 `--sample`

以下文件表、固定数量和构建命令仅描述冻结福冈样刊。`assets/fukuoka-reference/` 是已认可样刊的可构建源码与本地资产，默认静态摄影封面，含 10 章、4 天、20 个地点、48 条贴士及当时的旅行模式。它不包含此后全部当前引擎改进。以下历史文件结构不能用于指导新城市适配；新城市使用上面的默认分流。

### 样刊内容与代码归属

| 文件 | 修改内容 |
|---|---|
| `content.json` | `places`、`days`、`areas`、`sources`。地点有 id、中文 / 当地名称、类别、街区、说明、地址、停留、官方链接、导航查询词；每日包含停留点、具体时间、停留分钟、交通预留、预算、摄影 / 购物提示。 |
| `editorial.py`、`fieldnotes.py`、`practical.py`、`language.py` | 冻结样刊的城市介绍、街区、餐厅、48 条贴士、预约、伴手礼与日语卡；这些是历史内容位置，当前引擎主要使用 editorial-content.json。 |
| `magazine.py`、`build.py` | 卷首、刊头与封面、章节和目录文案、专题图文、编后记、来源、交付文件名。`build.py` 同时生成开发页和独立 HTML。 |
| `place-photos.json`、`editorial-photos.json`、`media/` | 冻结样刊的地点识别图、正文摄影角色 / 出处 / 原始尺寸 / 许可与本地图片。新工程的正文图表使用 edition-photos.json。 |
| `verified-coordinates.json`、`maps.json`、`maps/`、`map-ui.js` | 经核对的坐标、地图图片、标记和标签。替换城市时重做真实底图、地图边界、短地名、点位与路线，不只替换城市名。 |
| `app.js`、`schedule.js`、`ledger-model.js` | 时间轴、地点查询、旅行工具、存储、导入导出、成员与结算；福冈样例的币种、地名、总图投影、日程特例还在 `app.js` 中。 |
| `motion.js`、`art.js` | 当前位置、阅读反馈、动效开关与摄影动作。导航中的城市名、章节名称需要同步适配。 |
| `tokens.css`、`art.css`、`ui-polish.css` | 字体、色彩、比例、摄影叠字、裁切、最新 UI 规则。完整样式顺序由 `build.py` 保留，最后的覆盖层关系不能随意调换。 |
| `fonts/`、字体 CSS、`font_supplement.py` | 已有中文字体子集。更换长文后运行覆盖检查；缺字才补齐字体并重建。`Tokyo Sans` / `Bali Serif` 是内部字体别名，不代表目的地事实，不需批量替换。 |

样刊中的福冈、博多、天神、大濠、太宰府、四天、日元、日语及 `d2` 特例在原样恢复时属于正确内容。当前引擎迁移则按参考身份和目标身份检索正文，逐个区分合理比较、来源署名、内部字体别名与旧内容；不要把所有日本词或某个合法日程 ID 一律判为残留。

### 样刊构建

Python 3.10+；模板的 `requirements.txt` 声明 Pillow 和 fonttools[woff]。已有环境具备时不重复安装。以下在工作副本中运行：

```text
python -X utf8 build.py
python -X utf8 check-package.py
```

只在检查发现缺字或新内容确需额外字形时运行 `python -X utf8 font_supplement.py`，再构建。它通过 Google Fonts 补充子集，需要网络。原样恢复福冈模板的构建不需下载图片、字体或地图。

Node 检查使用 `package.json` 中的 jsdom、css-tree、fake-indexeddb；可以用现有依赖并设置 `JOURNAL_CHECK_MODULES` 为依赖目录，或在工作副本 `npm install` 后 `npm run check`。这两个检查只模拟 DOM 或计算静态级联，不是实际浏览器验收。Python 封装检查核对字体、内嵌资源、章节 ID 与静态封面。

福冈回归检查中的 4 天、20 地点、48 贴士和指定图版是参考版本断言，只用于样刊恢复；新城市使用当前参数化检查，不能挪用这些固定数量，也不为“通过”删掉有效检查。

样刊交付文件为 `福冈-四天三晚旅行杂志.html`。`index.html` 是依赖工作目录资源的开发页；样刊主交付使用资源内嵌的独立文件。新工作台的文件名配置遵循前面的默认流程。

## 实际浏览器验收

优先使用 [交付验收脚本](release-verification.md) 分配空闲端口并校验构建身份。手动预览也要确认端口属于本次服务、页面城市和标题正确、构建标识与磁盘文件相符；不能复用未知旧服务。若宿主不允许自动化访问 file://，可用本机服务，不改浏览器安全设置，也不声称已经实测双击路径。

有针对性地检查桌面约 1440px、手机 390px，长英文标题或密集导航额外看 320px：

- 封面主体、刊头粗黑横字、标题、天数和阅读按钮完整可见；图片不能放大糊掉或只剩天空。
- 目录中文名称可辨认，每个入口去正确章节；固定导航不遮标题，当前位置随滚动更新。
- 逐一检查所有片区专题及餐饮、文化摄影的主体、图注、正文是否对应。确认大图叠字和图文两列不重叠，手机按合理阅读顺序变为单列。
- 日期切换后时间轴、地图、交通、餐饮对应同一天；时间列对齐，下一站时间有交通余量。地图地名不挤成竖排。
- 地点搜索 / 筛选 / 收藏与详情正常；贴士主题、长条目和语言卡能读。
- 旅行模式打开、日期切换、地图展开、地点内的票据与参考附件、摄影、记账、关闭返回焦点正常；切工具不丢当天备注。票据在地点内检查，不新增独立票据主工具；当天行程保留紧凑语言入口，不恢复准备清单按钮。
- 动效开关能恢复静态画面；没有重复入场的整页 PPT 效果。手机内容不横向溢出。

按当前修改覆盖受影响部分；已经通过且未受影响的检查不反复跑。保存少量有代表性的截图并诚实记录模拟尺寸，不把手机视口模拟说成实体手机测试。无法实际浏览时明确标为待视觉验收。
