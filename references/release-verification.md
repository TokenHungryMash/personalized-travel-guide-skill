# 构建身份及交付验收

## 先确认正在检查哪份文件

构建器给页面写入 `travel-build-id`，输出 `build-manifest.json`，记录城市、slug、天数、文件名及 SHA-256。截图前同时核对页面构建标识、数据中的城市身份和天数、标题与磁盘文件哈希。HTTP 200、端口可访问、页面看起来相似均不算核对完成。

优先运行 `node <技能目录>/scripts/audit_browser.cjs <工作目录>`。需要 Node、`playwright-core` 和 Chromium 系浏览器。验收脚本自动查找工作台依赖与已安装浏览器，可用 `JOURNAL_CHECK_MODULES` 指定 node_modules，`JOURNAL_CHROME` 指定浏览器路径。脚本用操作系统分配的空闲端口，不复用未知服务、不终止别人的进程；还会故意更改构建标识，验证错误页面确实被拒绝。

脚本在 1440、390、320 像素宽度检查总览、放大按钮、所有每日地图、弹层地图、编号、源码泄漏和横向溢出，再通过 `file://` 打开同一交付文件，阻断 HTTP(S)，解码页面图片，记录实际请求及异常。报告与截图写入工作目录 `qa-hardening/`。这不替代地点库、旅行工具、记账和导入导出的功能验收。

## 当前工程的验收顺序

### 预览与正式交付分开

内容初稿完成、下载和嵌入大图之前，先运行 `python -X utf8 build.py --check --preview`。只读预检先查结构；结构合法后一次汇总正文完整性、来源、旅行模式、覆盖和审阅证据缺口。草稿阶段仍报告覆盖与审阅缺口，但不因此阻止试读；正式预检去掉 `--preview`。已有工作台也可用新版技能的 `python scripts/preflight_edition.py <工作台>`，草稿加 `--draft`。预检不生成 HTML，不下载照片或字体，不改写数据、清单 ID 或审阅状态；通过只代表数据检查通过。

当前引擎先用 `python -X utf8 build.py --preview` 生成供试读与浏览器检查的文件，文件名带“待验收预览”，manifest.stage 为 preview。它不能作为已完成成品交付。试读后补全当前内容的 editorial-review.json，再运行 `python -X utf8 build.py`：正式构建依次检查目的地及餐饮覆盖、内容审阅证据和图片质量，失败不生成新成品；通过后 manifest.stage 为 release。最后核对正式文件身份及受影响的浏览器检查。默认入口和直接渲染器均不得绕过此流程；直接渲染器默认只输出预览。冻结福冈还原不变。

覆盖检查使用工作台 `coverage_release.py`，技能侧同入口为 `python scripts/audit_coverage.py <工作台>`。依据目录规范核对城市类型、真实日数、有效地点与餐厅规模、四类推荐的适配、逐餐窗候选及其在旅行模式中的引用。不能用自报的小目标、机场或未定酒店锚点补数量；scopeOverride 只记录已有用户明确范围或有来源的当地客观可用性限制，人工核对依据；生成者的时间、素材和研究不足不是例外。旧工作台升级须同步当前构建及校验运行文件（包括 preflight.py、language_fields.py、offline_images.py 与 offline-image-pool.js 等依赖），保留该工作台的正文、配置、图片、存储身份及审阅记录；不要只替换 build.py 导致缺依赖。数量和映射通过不代表菜品、营业、预算、地理可用或文章充分，仍需实页走读。

正式构建失败时，磁盘上的旧正式文件可能仍在，不能把它当作此次产物；核对当前命令成功、manifest.stage、文件哈希与内容身份。本文后续的预览检查不等于正式交付成功。

### 实质内容的放行依据

新城市交付必须同时完成内容试读与浏览器功能检查，二者不能互相替代。`editorial-review.md` 保留主导条件与编辑判断；同一轮试读把可核对答案写入 `editorial-review.json`，不要再写一份空泛总结。该文件是内部证据，不显示在读者页面。

首次可运行 `python scripts/audit_editorial_release.py <工作台> --init` 生成待填写表，自动列出本期区域与旅行日；不会覆盖已有记录。生成表不算审阅通过。填好后去掉 `--init` 执行检查。

逐日条目的 `reviewTargets` 自动列出当前站点介绍、转场、餐厅与备选的字段位置，帮助找到需要阅读的材料；它不是 evidence，也不会填写 answer、pageLocation 或 ready。先按这些位置读实际内容，再打开当天旅行模式确认能找到，最后填真实审阅证据。内容或路线改变后重新核对目标，不靠增加引用数量代替阅读。

`inputHashes` 记录当前 `content.json`、`editorial-content.json`、`edition.json` 原始文件的 SHA-256；内容改变后重读受影响内容再更新，不直接刷新哈希假装重新审阅。`checks` 每项包含 `domain, question, answer, pageLocation, status, evidence`。`status` 只有确认完成才填 `ready`，未解决写 `pending` 并在答案中说明缺项。`evidence` 每项为 `{file, pointer, quote}`：file 为 content.json 或 editorial-content.json；edition.json 仅绑定配置身份，不作为正文证据。pointer 是指向具体字符串的 JSON Pointer，quote 是该字段的完整正文或其中以双换行分隔的完整段落，不引用标题、ID或截断词串充当解释。示例：`{"file":"editorial-content.json","pointer":"/portrait/0/1","quote":"从实际正文复制的完整段落"}`。

完整新刊的 domain 覆盖 `portrait:identity, portrait:formation, portrait:life, stays, culture, shopping, food_types, notes, preparation, languageScenes`、每个 `area:<区域ID>`、每个 `travel:<日ID>`。问题由初始化程序按章节职责生成且不可替换；城市身份、形成过程、当下生活分别回答，旧 portrait 单题不能代替。答案按采编工作流审读：城市讲当地背景，住宿比较取舍，文化指出观看线索，购物解释品类选择，准备给完成条件，语言从场景找可用表达及回答。每个 travel 答案同时检视逐站内容、用餐/补给、交通、购物是否适用、提醒与备选，附当天字段和相关地点字段摘录；交通日说明不适用项，不凑活动。旅行模式的回答不能只引用全书城市介绍。页面位置写实际章节/日期/入口，最终试读确认能找到。

`audit_editorial_release.py` 检查覆盖、当前文件身份、未完成状态、完整正文引用、所属章节/日次与摘录真实性；它不能判断答案是否真正回答问题，不能验证营业事实或页面可见性。执行者须逐条核对答案与原文、来源及实际页面，不用“evidence-linked”替代质量结论。旧稿局部修订可用 `--scope portrait area:east travel:d2` 检查受影响域，完整新城市不得缩小范围；改路线应包括受影响旅行日与关联专题。浏览器检查另验证页面渲染与查询状态。

当天证据必须指向实际站点介绍、每段转场文案、有关餐厅资料以及当天备选条件（实际适用才要求）。只有 move 和全程 budget 的记录不能证明旅行模式完整；餐饮领域也要引用真实餐厅内容，不能只引用一道菜的介绍。城市三问在整篇文章里分别检验解释是否充分，不要求正文三段一一对应，也不能由一句相关事实自动宣布整篇完成。

依赖尚未安装时在工作台执行 `python -m pip install -r requirements.txt`。内容字段与配图计划见 [编写约定](authoring-contract.md)；审计脚本参数标为工作台时，传目录而非其中的 HTML/JSON 文件。

默认新工作台仍是待编写的历史结构示例，须补完本期正文、来源、路线与合格素材，再运行 `python -X utf8 build.py --preview`。构建拒绝旧示例缺项属于预期门槛，不可通过关闭 `travelContentVersion`、`editorialEvidenceVersion` 或大图检查交付。以下命令面向当前引擎；`--sample` 冻结福冈恢复沿用其样刊检查，不能假定冻结样刊已具备后续功能。从技能根目录依次检查数据和生成文件。

```text
python scripts/audit_travel_content.py <工作台>
python scripts/audit_destination.py <工作台>
python scripts/audit_editorial_depth.py <工作台>
python scripts/audit_editorial_release.py <工作台>
python scripts/audit_maps.py <工作台>
python scripts/audit_directory.py <工作台>
python scripts/audit_fonts.py <单文件HTML>
python scripts/prepare_media_review.py <工作台>
```

字体检查以图注、署名、正文和旅行模式内容均已生成的最终内联 HTML 为准，不能拿图注定稿前的结果交付。当前渲染器在写出正式 HTML 和 manifest 之前自动检查配置字族各字重的中文覆盖，报告保存为 `qa-fonts/report.json` 并绑定本次 HTML 哈希；缺字则正式构建失败，旧交付文件和 manifest 保持原样。预览仍可生成，但明确报告缺字，不能作为成品。只读 `--check` 不渲染 HTML，因此不包含此项。

有缺字时，本次渲染已更新 `index.html`，在工作台运行 `python -X utf8 font_supplement.py`，然后重新正式构建。新补字按实际字族和字重追加，重复运行应复用已完成的子集。下载失败时保留原字库与 CSS，排查网络后重试。任何后续图注或文字修改都须重建，不能沿用前一次字体报告。旧工作台升级时同时带上 `font_audit.py` 和当前渲染器。

`audit_editorial_depth.py` 不按字数判定质量，检查正文复用导语、跨区域重复体验和多地点重复提醒，并要求已有页面试读记录。它仅检查记录存在，不能认证记录真实或充分；须按实用内容编写契约提供页面里的具体答案。候选须逐条回读，不能靠复制提醒或空填审阅文件放行。新城市与正文修订运行，纯样式修订不额外增加这项。

`audit_destination.py` 检查结构化正文、餐厅引用和天数，不扫描 base64 或内部 CSS 字体别名。旧目的地词会列为待审上下文；核对是否是合理比较或残留。改日程后同步审阅餐厅 `why/fit/note`、预约、摄影、备选和地区专题，尤其是数字仍合法但对应日期已变的情况。

`audit_maps.py` 检查主线站点覆盖和顺序、标号、图片与投影尺寸、非有限坐标、图外地点及旧图钉位置。跨区日以全部站点决定底图边界，再重算图钉。无坐标的地点保留文字索引；历史地图缺投影参数时，审计会明确列出地理位置待实看的范围。

新城市完整构建后运行以下基线检查；已有手册修订按本页末尾范围表选择，不要求每次重跑全套。需安装依赖时在工作台运行 `npm install`，或设置 `JOURNAL_CHECK_MODULES` 为已有 node_modules 的绝对路径；浏览器可用 `JOURNAL_CHROME` 指定。显式路径错误时先修正路径，避免把环境错误解释成产品缺陷。

```text
node scripts/audit_browser.cjs <工作台>
node scripts/check_current_engine.cjs <工作台>
node scripts/check_travel_interiors.cjs <工作台>
node scripts/check_travel_copy.cjs <工作台>
node scripts/check_reader_reference.cjs <工作台>
node scripts/check_editorial_layout.cjs <工作台>
node scripts/check_editorial_structure.cjs <工作台>
node scripts/check_ledger.cjs <工作台> --browser
```

逐张实看地图拼图与正文配图清单，并在最终页面上确认片区、标题、图注和主体相符。实际用到的图片或文案变更后，重建再重跑受影响检查，确认报告哈希与最终 HTML 一致。

`check_travel_copy.cjs` 补充逐日旅行模式内容核对：当天与逐站限制、介绍、购买建议、摄影内容、网页链接标签，以及韩国导航服务名称与实际目标。它还检查附件存储读取失败时内置摄影建议继续可见。备份故障分支须生成明确标为不完整的备份（`attachmentsComplete:false` 及对应文件名／提示），不得把丢失附件描述成成功的完整导出；导入此类备份时保留已有附件，旧备份格式继续兼容。此检查不替代打开真实来源验证营业时间，也不替代实际上传、删除、头像与完整备份往返。

`check_reader_reference.cjs` 核对新餐饮、准备和语言速查：逐日用餐候选与 `days[].dining` 一致，餐厅副本与正文的介绍、来源相同，地点详情返回保留展开状态；新旧清单 ID、同页勾选、计数、重载和备份保持一致。语言卡包含大字展示、必填食材未完成时阻止展示、读音与常见回答，正文副本不得产生重复 ID。在 320/390/768/1440px 检查速查弹层无横向溢出；保留现有四个工具及其日次与返回位置。脚本核对最终文件 SHA-256，结果和截图写入 `qa-reader-reference/`。数据契约测试运行 `python -m unittest discover -s scripts -p test_reader_reference_validation.py`，覆盖旧格式兼容、重复 ID、场景完整映射、缺失英语、共享填写对象、错误输入形状、非法用餐地点与缺失来源；结构通过不代表当地语言翻译或餐饮事实已核实。

## 阅读结构与目录对比度

`check_editorial_structure.cjs` 使用最终单文件和 `build-manifest.json` 校验 SHA-256，输出 `qa-editorial-structure/report.json` 及 320/390/1440px 的城市、区域、住宿和目录截图。它检查：

- 正文先为 `orientation → neighbourhoods → itinerary → food`，页面目录与弹层目录的完整顺序和实际章节一致。
- `#journey-overview` 属于行程章；城市与住宿区没有日次安排文字。每个 `area_sections` 的正文小节实际出现，绑定来源的链接数量与页面一致。
- 上述尺寸没有横向溢出；深色页面目录、浅色弹层目录的说明小字分别达到 4.5:1，计算样式 `opacity` 为 1。
- 行程最后一天的继续阅读入口指向 `#food`；没有页面脚本异常。

人工试读同时核对章节职责：城市开头让人认识目的地，住宿解释区域差异，地区正文给出当地具体内容，体验旁栏提供不同信息。遮住“第几天”等路线标签后，这些章节仍应成立；完整路线与时刻由行程承担。对照 `areas:<区域ID>`、`experiences:<区域ID>`、`food_types`、`snacks` 的每项来源，确认链接位于所支持的正文旁边且确实支持该事实。链接数量通过不能证明引用对应正确，日次词扫描也不能证明文字实用。

按 [旅行编辑语言](travel-editorial-voice.md) 检查空泛开场、重复总结、整页相同句式与内部制作话术，保留影响选择的数字、营业条件和不确定性。该脚本以减少动态效果模式检查稳定阅读状态，不能替代正常动效、旅行模式、记账、头像、备份、地图与照片实看等既有验收。

## 照片压缩与成品大小

MPO/JPEG 内含增益图不代表动画，离线压缩应取静态主帧；真正的多帧动画仍保留。旧工程同步压缩模块和增量字体补字脚本，新增图注后先生成最新 `index.html`，再补字、重建并复核字体，避免补字仍读取上一版正文。

离线内联默认使用 WebP，按用途限制最长边：封面 2560、正文跨页 2000、地点图 900，quality 84；这些是压缩后的尺寸上限，原图仍先通过本文末尾的大图最低质量门槛。不放大小图，不改源文件，地图保持原字节，透明信息保留。同一源图/用途的转换结果复用不等于允许重复正文大图；不同大图位置仍须按去重检查。静态正文可直接阅读。`index.html` 是引用原素材的开发页，体积与加载验收针对单文件交付件。

需要覆盖参数时在 `edition.json` 写 `offlineImages`：`coverMaxEdge`、`spreadMaxEdge`、`placeMaxEdge`、`quality`、`warnMiB`。默认 `deduplicate:true` 将重复的同一图片载荷只存一次，保持图片字节与清晰度；首个静态图片保留直接来源，其余引用在应用启动前还原。读取交付 HTML 中 guide-data 的浏览器检查须等待这一步，不把磁盘中的共享引用当作丢图；原始 content.json 和用户上传附件不受影响。此项节约的是文件体积，不承诺同比减少浏览器解码内存。

构建输出 `qa-size/report.json`，记录源与内嵌尺寸、每图体积、逻辑出现次数、转换缓存命中及最终文件 SHA-256。`compressionSavedImageBytes` 与 `dedupSavedImageBytes` 分别记录编码压缩和文件内去重收益；`imageBytes/repeatedImageBytes` 按最终实际存储计，不能把缓存命中当成已经去掉重复载荷。默认超过 30 MiB 报警；这不是手机兼容性的保证，应检查占用最大的图与重复内联载荷，再在实际交付文件中实看细节和断网加载。底图不参加照片有损压缩。

截图/QA/构建产物不进入新的目的地工作台和技能 ZIP；按用途识别文件，不依赖成品文件名语言。`dialogs.html`、maps 内的地图渲染输入与冻结样刊资源保留。打包脚本校验 ZIP 完整性和非 ASCII 文件名的 UTF-8 标志。

## 七类回归必须防住

1. **串页与旧文件**：使用上面的身份与哈希核对，旧截图作废。构建后修改任何代码或素材都要重建；交付前报告哈希必须等于交付文件。
2. **模板表达式漏出**：检查浏览器最终文字，不只做源码语法检查。页码从天数生成，不能出现 `undefined`、`${…}`、`*String(…)*` 或 `.padStart(`。
3. **地图缺编号**：编号以地图路线 `ids` 的顺序为准；共享 `map-layout.js` 归一化坐标与编号。未知地点及无效坐标不生成点，保留列表说明。缺字段不能变成“undefined 机场”。
4. **跨城市残留**：检查显示文字、默认查询、备份失败提示、面包屑、语言、币种和存储键。旧旅程保留存储键与 `backupFormat`，动效键仅通过明确列出的 `legacyMotionKeys` 迁移；新工作台使用独立身份，不能继承上一旅程的数据。
5. **照片身份错误**：按缩略拼版逐图看主体，并对照来源页、地名及分店。菜名可能对应山名、动物或异地同名地点；通用机场必须核对国家、城市或机场代码。菜式、品牌、邻近桥梁和区域照片不能当作具体餐厅门店照；图片能加载不代表照片正确。缺图按地点库标准记录例外并用完整文字行，不摆空相框或假图。不要把过往照片说成当前店貌。
6. **底图不可用**：检查真实瓦片内容、覆盖范围及来源署名；API KEY REQUIRED、水印错误页、空白图即使状态码成功也失败。山区行程要有能读懂的地形或地形说明。更换服务时同步署名，不残留上一家服务名称。
7. **地图可读性**：为中文手册编写简短中文地名，机场代码放详情。共享布局在最终屏幕尺寸实测文字，避开边界、编号与其它标签，不能只依赖固定像素偏移。拥挤时隐藏个别名称、保留编号和对应列表；不能移动真实坐标。地图缩放按钮沿用纸色、字体、边线、焦点与至少 44px 点击区。

## 字体与如实交付

运行 `python scripts/audit_fonts.py <单文件HTML>` 检查内嵌中文字符覆盖；问卷可运行 `node scripts/audit_intake.cjs <问卷HTML>` 检查填写、下载和展开后的布局（依赖设置同上）。新增中文后检查正文与衬线字体各自的字符覆盖，不以系统回退字体“看起来有字”代替离线字体验收。补字后再构建；问卷也需内嵌字体。地图及图片来源必须实看，不能把自动测试通过描述成全部内容事实核验。

报告记录实际城市、构建标识、文件哈希、视口、功能与截图、网络请求数、异常数，以及未完成项。照片覆盖不足或内容尚未重新核实要明确写出，不因框架测试通过就宣称全量验收完成。

## 事实、日期与验证范围

新城市与正文修订先按 [实用内容编写契约](practical-editorial-standard.md) 完成 `editorial-review.md`：记录目的地主导条件、章节取舍及读者实际能完成的决定；旅行模式四个工具也在范围内，尤其逐站介绍、日程限制、购买建议、备选与摄影，不只通读外层章节。对会限制本次路线的场所按 [营业与日历核对](opening-and-calendar.md) 留存 `opening-hours-review.json`，逐项区分已匹配、已改线、日期未定和未能确认。没有这两份实质审阅，不以来源链接数量或字段检查代替内容验收。日期未知可以交付条件路线，但页面必须指出受影响的日次、触发条件与处理方式。

行程已有明确日期时，核对当天星期、节假日、馆休和预约日历，必要时按用户认可的路线调换游玩日。仅有天数时使用相对旅行日，避免擅自选日期并呈现为订单。用户明确要求离线研究或跳过实时核验时记录该要求，并在交付中说明营业、票务、价格和班次尚待按实际日期核对。

自动检查通过、图片主体实看、资料时效核查分别记录实际范围。手机视口检查注明模拟尺寸；缺图记录具体地点及尝试结果，交付说明覆盖率。模板字体别名和无引用的历史研究文件按技术用途处理，避免误当成正文残留。公开传播素材的许可按实际来源核对。

## 素材实看与从头制作

- 新底图来源先取一张实际目标区域的样图并打开查看，确认是有效地图后再批量生成。发现把访问限制渲染成图片的瓦片时，立即换可用来源，重做受影响的图并更新署名。HTTP 状态和图片解码检查只负责传输与文件格式。
- 批量完成后运行 `python scripts/prepare_media_review.py <工作台>`，打开 `qa-media/map-review*.png` 检查全程总图和每张日图，并查看 `editorial-review*.png` 中的正文照片及章节对应。完整标题、用途、来源和文件哈希保存在 `qa-media/media-review.json`。瓦片拼缝、局部提示或缺块可疑时打开原尺寸底图。再检查最终 HTML 上的标签、署名和图层。浏览器脚本通过仍须实看地图画面。
- 从头制作时，可重复加 `--compare <旧样刊素材目录>`，对本期实际选用的照片和历史素材做指纹比对。报告中的相近项要打开对照，确认同图就更换。另比对来源 URL 与构图，识别指纹容易漏掉的大幅裁切和改色。旧版目录仅供比对，地点事实、照片和地图从新来源取得。缺少合适照片的地点用文字卡，在交付时说明覆盖范围。

## 清迈生成回归补充

图片下载遇 Commons 403 时，优先查已标明原作者与许可的可靠镜像或旅游局地点页面；逐图核对身份后使用，保留原始来源与下载来源。禁止靠未知文件名反复拼图。

地图遇 API KEY REQUIRED 或 403 图片，必须更换实际渲染路径。先取得一张样图实看，再批量输出。可用 OpenFreeMap + MapLibre 导出真实矢量底图，固定并检查依赖的入口类型，不能假定最新版仍提供 dist/maplibre-gl.js。地图仍需逐张实看，地点坐标必须有实际查询证据，导航链接本身不能充当核验来源。

默认脚手架清理上一城市的单文件交付件，复制后保持 reference-needs-authoring。新增文字后检查字体覆盖，缺字才运行 font_supplement.py 并重新构建。

## 大图质量门槛

维护已有工作台时，先确认其 `build.py` 已调用当前 `audit_photo_quality.py`，不能因技能目录已有检查脚本就认定旧工程会执行。缺少接线须补齐后重新构建；新脚手架回归应保留新引擎，只迁入临时测试内容与素材，确保旧工程没有掩盖质量门槛。

`build.py` 在正式构建的内容审阅通过后运行工作台的 `audit_photo_quality.py`（预览构建同样检查图片）：封面源图长边至少 2400、短边至少 1400，正文大图长边至少 1600、短边至少 900；检查 EXIF 方向后的真实像素。每个 `mobileSrc` 同样按所在位置检查。不同正文位置若字节相同或感知指纹近似，构建失败并列出位置和文件。同一位置的桌面／手机替代图不互相判重复；地点识别缩略图允许复用。报告写入 `qa-photo-quality/report.json`。不以插值放大过关；找不到合适原图时换素材或改为非大图用途，并同步数据与版式，仅缩小 CSS 不会豁免仍在大图引用中的源文件。像素门槛无法识别失焦、运动模糊和重压缩，仍需在最终单文件中以实际显示尺寸检查每一幅大图，以及手机裁切和叠字。

运行 `node scripts/check_directory_layout.cjs <工作台>` 检查正文通栏和操作行位置。地点库同时检查 589、390、320 像素宽度：缩略图只和题头并排，长正文与操作行占满整行；摄影来源不得悬浮遮图或造成不规则缺口。


## 按改动选择检查

同一次修订先收齐相关代码、文案和样式改动，再构建一次；新增文字缺字时补齐后再构建。报告绑定实际构建，后续只重跑受新变动影响的检查，不为未变模块重复截图。新城市仍完整覆盖资料、图片、地图、阅读及所有旅行工具。

| 改动 | 重点检查 |
|---|---|
| 仅技能文档 | 链接、规则一致性、audit_package 与宿主 quick_validate；不重建东京。 |
| 内容与路线 | 受影响的数据／来源／营业日历，正文与旅行模式同源呈现；改路线才重查地图和相邻日次。 |
| 语言与速查 | check_reader_reference、check_language_glossary、check_readability；引擎改动另测英语单语分支，核对无重复按钮、字段及显示内容。 |
| 旅行模式版式 | 受影响工具的桌面／320／390尺寸、折叠、导航、输入与返回位置；纯间距调整不重新核实全部餐厅。 |
| 记账或备份 | check_ledger及相关附件／头像／数据往返；保留旧记录和失败分支。 |
| 摄影、地图、导航 | 对应质量、版式或地图脚本与实看；不修改的素材无需重新下载。 |
| 通用引擎或脚手架 | Python回归，受影响浏览器检查；复制／加载／身份适配变动需隔离新工作台验证。 |

未重跑的旧报告只能说明其记录的构建与范围，不改哈希冒充本次全量验收。
