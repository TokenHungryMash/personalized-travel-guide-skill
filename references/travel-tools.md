# 旅行模式：阅读、上传与出片建议

旅行模式分当天行程、旅途笔记、摄影参考、记账结算。它与杂志正文共用所选日期及本机记录，四个工具的内容范围不同：行程、摄影和当天备注按日；全程笔记不随日期变化；附件有全部／当天筛选；账本保留全程记录并提供筛选。日期切换不意味着其他天的账目被隐藏或删除。更新现有手册保持原存储键和备份格式。

当天行程提供当天用餐候选与紧凑的随身语言入口，不放准备清单按钮，保留现有四个主工具与「当天提醒与备选」合并入口。新增查询不能迫使用户关闭工具、跳到杂志正文后丢失当天和阅读位置；本期内容与本机记录继续共用，不能另建一套状态。

## 阅读层级

- 普通正文 16px 左右、行高 1.75–1.9；次级说明至少 13px，输入控件至少 16px。用留白和细线分组，不用满屏小字压缩内容。
- 手机边距 16–20px；大段文字不要与细窄时间列相互挤压。日期和工具导航要有明确选中态，按钮有效触达区域至少约 44px。
- 笔记区区分全程共用与当天备注，切换日期不得清空或串用。关闭工具返回原来的阅读位置与焦点。
- 手机阅读正文行程时使用固定底部日期导航，最多 7 天直接露出全部日期，超过 7 天改为日期选择器与前后日按钮；不能让主要日期入口滑出后无法发现。底栏只在行程章显示，遵守安全区域，弹层打开时隐藏，正文预留底部空间。当天末尾提供明确的「下一天」和下一日区域，最后一天进入美食 `#food`；不自动跳日、不劫持滚动，也不把手动切日冒充已读进度。日期短名来自 `days[].dockLabel`，完整路线仍保留。
- 旅行模式优先露出当天时段、地点和导航。手机可合并重复的大号日期、缩短题头和站间空白；导航与地点详情直接可点，票据与外部参考可放进明显的展开项。次要信息仍可访问，不能为紧凑删除交通、天气或完整地点提示。外层底栏与弹层日期共用一个状态。
- 上传用统一的“＋ 添加照片／票据”按钮；原生文件输入透明覆盖按钮，保留键盘焦点、可访问名称和浏览器原生选择文件功能，不能只隐藏 input 后留下不可键盘操作的装饰。
- 文件类型、单文件大小只在上传处写一次。空相册不再同时堆叠“给当天存几张”“还没有照片”“可以保存构图”三段话。存储与备份说明放在折叠帮助里。

## 工具内的用餐、准备与语言

当天行程通过 `days[].dining` 直接提供与当前日期、区域和用餐窗口对应的餐厅候选。紧凑显示店名、位置、吃什么与适合的餐次，按需展开预算、营业限制、菜单与来源，可打开地点详情和导航。主线、顺路备选与需要额外路程的选择说明角色，不能把餐饮章所有店一股脑塞入每天；候选引用不会改变 `stops`。日期未定或未订位时保留实际条件，不显示已安排的假象；切日更新对应候选，详情返回保留当天及展开位置。

当天行程不显示准备入口；正文与速查兼容入口保留完整三阶段任务及勾选进度，语言入口按场景显示完整会话、常备词与常见回答，非英语目的地可切换当地语言及备用英语并放大出示；不能只留几句摘要或一个返回外页的链接。静态 main 正文是唯一渲染来源，速查复用其 DOM 并清除重复 ID，控件与辅助名称仍须正确对应。阶段和辅助内容按需展开，语言场景用紧凑入口切换，不重复堆叠分类，手机能快速定位。准备项在这里勾选后，正文同一任务即时更新，关闭、重开、刷新与备份往返后不串项；语言的读音、用法、常见回答和放大出示同样可用。过敏表达等必填内容未选时，不得显示成完整卡片。

返回当天行程时恢复所选日期与原阅读位置；从任一原有工具切换也不能丢失未离开前已保存的笔记、账目或附件。外部菜单、来源与地图明确是联网链接，正常的内容查询与准备勾选应可离线完成。

## 当天提醒与备选：统一折叠入口

`days[].alternatives` 使用 `trigger, title, replace, route, time, traffic, check`。`route` 是地点库 ID 数组；纯休息、直接去酒店等无确定地点的方案可以为空，不编造住处或机场接送点。其他字段分别说明触发情况、方案标题、替换哪段、预计时间、交通走法和先确认什么。

完整游览日至少 2 个实际有用的方案，通常 2–3 个；触发条件按当地路线选择，例如雨天、没票／闭馆、少走路，也可以是停航、道路封闭、炎热或高海拔不适。抵达／返程至少 1 个保护交通衔接与休息的方案，不把未知接送写成已安排。不要每天复制同样三条，也不要为凑数量推荐不顺路的远点。时间写为建议估算或已确认预约时长，和实际营业、票务区分。

旅行模式将当天 `guard` 与 `alternatives` 放在同一个默认收起的区域，入口统一显示「当天提醒与备选」及备选方案数量，不再单独铺开一块当天提醒。展开后先显示 `guard`（有内容时），再显示备选方案；每个方案仍独立折叠，先看触发情况与标题，按需打开替换段、时间、交通、确认条件及地点详情／导航。`alternatives` 为空但 `guard` 有内容时，入口和提醒仍须显示，不能因没有备选而丢失提醒。

只有提醒或只有备选时，标题可相应简化为「当天提醒」或「当天备选」；没有方案时不放空列表，二者都为空时不显示这一入口。

每个方案说明保留和替换的段落，起点或衔接位置、建议停留与新增交通，必要的费用或票务差异；`check` 给具体确认对象和入口，不只写“看天气／查官网”。雨天不把露天公园当可靠雨备；闭馆不假定邻馆一定开放；需要预约的活动明确确认条件；跨区备选说明增加的交通。选一个地点还是顺序走多个地点必须写清，不能把地点数组中的所有候选暗示成必须走完。

查看提醒或备选不改变已批准路线，不提供应用路线、删站或自动重排功能。打开地点详情再返回，应保留当天、统一入口及已展开方案的状态；切日同步更新提醒、备选内容和数量，不能混用另一日的信息。构建校验缺字段、未知地点和逐日覆盖；人工检查方案是否真的适合当天，程序不能判断天气或可用票。

## 出片建议数据与内容

新城市按实际路线编写 `days[].photoPlan`，数量与例外统一按下方「内容最低量」执行。纯交通日可为空；用户不想安排摄影时按其要求减免，不为了摄影改动已批准路线。

每条使用 `time, placeId, title, light, composition, portrait, settings`：

- 具体地点与大致拍摄时段；光线写天气、季节条件，未知出行日期不能保证某个钟点就是日落或蓝调。
- 构图给可执行做法：拍摄方向或可进入区域、前景／背景、横竖幅和取舍。未知机位或不允许进入的屋顶不要编造。
- 人像／穿搭结合环境色彩、人物站位与现场通行。建议是选择，不强迫换装，不以堵路或拍陌生人换取效果。
- 参数是可试的起点，不能声称固定值适用于所有光线。优先按用户在会话或其他说明中自愿提供的设备；新版问卷没有独立设备题。未提供则用手机主摄建议，不继承原版示例的 A7C II 型号。
- 室内、展品、宗教地点的禁拍和器材限制写在相关地点，避免每天复制同一句空泛提醒。引用照片须对应地点，用户上传参考图独立保存。

旧版 `shooting` 字符串可兼容显示；新内容不要用兼容字段代替完整拍摄建议。当天行程只放“查看今天的出片建议”入口，完整方案集中在摄影参考页，减少重复。

## 检查范围

新城市在桌面与 390px 手机视口实看四个工具；已有手册按 [交付检查范围](release-verification.md) 只复查受影响部分。密集导航另测 320px。检查字号、边距、长文件名、无照片和有照片状态；实际上传小图、切日、重载、预览、删除；票据与摄影图不可混到另一日。按天检查拍摄建议有区别，正文不重复。账目按 [记账契约](ledger-contract.md) 验收。

新增入口另检查：逐日用餐候选与完整餐饮资料一致且不改路线；三阶段任务可定位、勾选与正文同步；重排后旧勾选仍属于同一任务；已编写的全部语言场景均可在工具内完整阅读、展开辅助信息和放大出示；必填过敏食材的未选／已选状态正确。速查打开时无重复 ID，控件仍可键盘访问。往返原有工具、地点详情、准备与语言后，日期、焦点和阅读位置保持正确。不能只验收外层准备章或语言章。


## 内容最低量（新作全查，修订查受影响内容）

`days[].periods` 分别对应上午、下午、晚间，必须写该时段实际安排；不能拿 `lead`、`move`、`guard` 三段全天文字填充。逐段对照时间轴、开门与入场条件；抵达、返程时段受未知航班影响，就明确条件，不强行填满三段活动。

交通标签区分乘车／步行时间与整个站间间隔。如果间隔含午餐、排队、休息或自由活动，要明确列出；不能把 120 分钟间隔描述成 120 分钟列车车程。标签已有分钟数时，外层时间轴和旅行模式都不重复追加同一数字。预算说明对应当天实际餐馆与门票口径，原路线与便宜替代方案分开，不把一餐价格包装成全天预算。

旅行模式每个主线站直接显示 `desc` 介绍、`walk` 建议走法、`tip` 现场条件，不设合计字数门槛，按地点性质讲清内容；交通站解释识别站位和使用方法，不扩写成景点散文。`desc` 先讲地点本身，`walk` 给实际观看或使用顺序，`tip` 只留影响体验的条件；三段不要重复一句结论。构建检查字段缺失与重复，深度由地点实际能回答的问题判断。当天 `guard` 放在「当天提醒与备选」统一折叠区，各站日程限制仍在对应站点显示，与该站 `tip` 相同时合并；不能因折叠或压缩界面丢掉营业、天气、预约或衔接限制。

有游览停留的日子至少保留一项真实地点的摄影建议；按独特场景增加，不因天数位置要求固定三条，也不把同一地点换标题重复收录。每条必须包含 time、placeId、title、light、composition、portrait、settings，不设摄影总字数或单字段字数配额；给出当前地点的取景、光线、人物与设备操作即可，简短但具体的建议优于重复模板。禁止用 shooting 一句话兼容字段代替完整方案；具体内容分工见上面的出片建议规范。

用户明确要求精简或不安排摄影时记录例外原因，可减免摄影数量和篇幅；仍然提供的条目必须有必要字段，并引用当天真实地点，不能因为填了例外就跳过数据完整性检查。逐日核对摄影内容的差异与路线相关性，避免复写通用段落。构建前运行 `python scripts/audit_travel_content.py <工作目录>`，并实看 390px 地点正文与摄影页。

新工作台自动设置 edition.travelContentVersion=1，build.py 会调用与独立审计相同的内容校验，失败时停止构建。旧样刊兼容显示；修订旧手册内容时启用该版本。纯交通日无论位于首尾还是行程中间，都允许零摄影方案；用户明确减免时记录 days[].photoExceptionReason 原始需求供人工核对，不自行填写例外。手机日期短名使用 days[].dockLabel，建议 2–4 字，完整路线保留在标题与无障碍名称。

## 手机内页一致性

旅行模式四个工具都使用主刊纸色、墨绿操作区、衬线题头与统一输入控件，不能只更新杂志外层。`travel-interior.css` 之后仍有当前 Impeccable 样式，加载顺序统一见 [当前引擎](current-engine.md)，不要把某个历史增强层移到末尾。笔记标题中的 label 继承标题字号；手机输入保持 16px、按钮触达区域约 44px。账本的总额、录入、明细、结算要能直接定位。

用户上传的摄影参考与附件预览使用 contain 完整显示，不按封面规则裁掉构图；头像才采用中心方形裁切。大图封面、街区摄影与地点识别图的裁切继续逐张实看。验收真实上传竖图，检查顶部与底部都保留，并测试预览、日期隔离与删除。

运行 `node scripts/check_travel_interiors.cjs <工作台>`，覆盖 320/375/390/414/768 宽度的四个工具、账本内部定位、演示案例与原账保护、竖图及预览，再跑原有上传、头像、多币种记账和备份回归。

正文或旅行模式修订后运行 `node scripts/check_travel_copy.cjs <工作台>`，逐日检查 `guard`、逐站介绍与日程条件、购买建议、摄影方案。「当天提醒与备选」须检查默认收起、收起时数量正确、展开后提醒在备选之前、各方案可独立展开、地点详情返回保留状态、切日信息对应，以及只有提醒而无备选的状态；桌面与手机采用同一规则。同时检查网页链接不会标作 PDF、地图服务名称与实际目标一致。附件库读取失败时仍应显示内置摄影方案，并明确报告附件读取失败，不能将它显示为空相册或让整页建议消失。

备份若无法读取附件，必须明确标为不完整：`attachmentsComplete:false`、文件名和提示均指出缺少附件；不能提示“完整备份已导出”。保留原附件并排查存储后重新导出。旧备份缺少这个新标记仍按兼容格式读取，但导入不完整备份不能静默清除本机原有附件。自动检查与人工验收均区分完整备份往返和附件故障分支。

`days[].shopping` 按当天区域和用户需要编写。有明确购物安排的完整游玩日通常给至少两条有差异的建议，说明具体品类、适合用途、判断依据、携带或预算条件。自然、纯交通、无购物意愿等日子不凑购物项目，可写实际补给安排，或明确当天没有购物安排。抵达返程以补给和交通缓冲为先，不虚构免税、库存或营业窗口。禁止把同一句购物口号复制到每一天；购买建议与正文购物专题交叉核对，长解释保留一处。

当前旅行工具与语言控件：顶部四个旅行工具，票据与参考由各地点入口管理；旧附件、备份及杂志内附件管理继续兼容。语言采用同页场景切换，正文与速查共用样式；旅行速查已有标题时不再重复内层标题和介绍。当前句子19px、中文用途16px、词语17px、释义15px，读音及说明按需展开，明显的加减号和至少44px触控区保留。手机检查短场景名称单行及同排等高；紧凑来自合并入口与减少留白，不靠缩小正文。
