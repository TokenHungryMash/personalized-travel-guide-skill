# 内容与功能：完整、分层、能查

正文必须同时遵守 [实用内容编写契约](practical-editorial-standard.md)：按章节职责组织，介绍章节先解释地方与对象，选择章节比较依据，现场贴士再给操作与限制。旧版正文最低字数已取消，按固定职责问题及实际页面回答验收内容。

## 阅读顺序

当前引擎默认 10 章；这是实现基线，不是所有目的地的内容配额。每日停留数与篇章组织按需求决定；地点与餐饮候选规模按 directory-standard.md 的目的地规划基线落实，不能随意压缩。确需增减章节时同步渲染器、目录、动态导航、锚点与相应验收，不能只改标题或 JSON 就宣称已支持。用下表检查功能覆盖；更丰富的内容可以放在有明确名称的折叠项内，不整块删除。

默认阅读顺序：认识目的地 → 街区与当地生活 → 每日详细行程 → 美食与餐厅 → 文化与参观 → 购物与伴手礼 → 交通与实用贴士 → 行前准备与语言 → 地点库 → 随身工具。先认识地方与区域差异，再进入具体行程。总路线图归入行程章；熟悉目的地的人可从目录直接进入。重排须同步正文、两处目录、章节编号、当前位置名称和章末继续阅读链接。

| 内容域 | 应该回答的问题 / 保留功能 |
|---|---|
| 城市介绍与住宿 | 城市在哪里、地理与历史如何影响今天、生活与饮食文化、季节特征；住宿介绍区域环境、生活便利、交通连接与取舍，不按当前日次定义住宿价值。实际订单单独记录。总览底图移到行程章，保留全部与分日查看。 |
| 街区指南 | 地理位置、街道与空间差异、文化与生活背景、具体可看内容、适合的兴趣；区域内部的观看线索可以保留，跨区路线和早中晚次序放行程。相关日程用短注或链接。照片与实质正文相连，不用体验摘要代替地区介绍。 |
| 每日详细行程 | 每站开始 / 结束时间、停留分钟、交通方式与预留时间、用餐与休息、当天预算估算、天气备选和晚到取舍。日期切换保留，路线编辑取消。 |
| 美食与餐厅 | 菜式、食材、口味和点法，再用值得专程吃、当地特色、日常连锁、咖啡与甜品四类推荐帮助选择；每店有准确分店、菜单、预算与营业条件，当天用餐候选在旅行模式可直接查。分类按当地情况调整，不凑品牌与数量，区域推荐不能冒充具体已订餐厅。 |
| 购物与伴手礼 | 去哪个街区、买什么、食品保存、尺码 / 重量、购物时间与用户愿望单。免税等规则按实际日期核对。 |
| 景点与文化 | 场所来历、看什么、预计耗时、开放与票务、参观礼仪；避免只堆一句“必打卡”。 |
| 地点库 | 中文和当地名称、类别、街区、照片、说明、停留时间、详细地址、来源、收藏、搜索、筛选、外部导航；移动端图片、标题、说明与操作共享对齐线。 |
| 交通与贴士 | 抵达返程、市内交通、行李住宿、吃饭付款、网络日常、天气雨备、购物礼仪、问路求助；每条包含具体情境和行动，必要时给备选与来源。 |
| 行前准备与语言 | 按三阶段给具体任务、操作入口与完成条件，保留稳定勾选标识；不默认国籍或签证资格。语言先按实际场景定位，再在同处查词、选句或读常见回答；按下文的英语／非英语分流，完整句能放大出示，读音与用法按需展开。当天行程提供语言小入口，准备清单保留在行前章节与速查兼容入口，离线联络卡仍保留。 |
| 随身工具 | 旅行模式、摄影参考、票据和照片附件、笔记、账本、成员、分摊与还款、预算、导入导出。工具切换保留所选旅行日和对应笔记。 |

## 先选体验，再安排路线

以读者的旅行目的建立候选池，综合当地代表性、当下关注度、体验差异和兴趣匹配，再判断时间、地理与预算。年轻读者可能为餐饮、音乐、社交、运动、设计、购物或当代文化专程出行；传统景点之外也应观察目的地正在发生的生活。热度是选题信号，不等于品质保证或适合所有人，不预设固定品牌、店名或必选数量。

先确定值得占用旅行时间的体验，再优化动线。高相关但不顺路的选择应说明需要替换哪半天、额外交通和适合人群，不能因为不在旧路线旁就直接忽略，也不能塞进已经排满的一天。主线、替代选择与地点库共用详情；推荐活动应交代实际体验、停留、入场方式、预算范围与适合的时段，而不是只加一个名字。说明营业时间和活动班表的区别，不把建议时刻写成已确认场次。

## 餐厅推荐要能直接做决定

介绍特色菜时，接上经过核实、能定位到具体分店或摊位的候选。默认采用以下四类推荐框架；先按当地餐饮与读者需要选店，不为填栏目补入无关品牌或重复店铺。

| 主分类 | 推荐理由与边界 |
|---|---|
| 值得专程吃 | 餐饮本身值得额外路程、预约或较多时间；写清具体特色、时间与预算代价，不把贵或有热度直接等同于值得专程去。 |
| 当地特色 | 能认识当地菜式、做法或用餐文化的具体店；解释吃什么与怎样点，不只写一个地方菜名。 |
| 日常连锁 | 当地实际营业、菜单与选择较易预期的连锁分店；准确说明品牌和分店。“熟悉口味”不自动等于连锁，“省心”也不是食品安全保证。 |
| 咖啡与甜品 | 适合坐下休息或为饮品、点心而去的店；区分咖啡馆、甜品店和仅外带的窗口，营业时段与用餐用途相符。 |

一店只设一个主分类，按这次推荐最主要的理由归类；平价、饮食限制、适合早餐等是补充信息，不另建重复卡片。四类是默认框架，不要求每类相同数量；缺乏合适候选时按目的地调整，不把独立店伪装成连锁。市场、夜市与餐饮街作为区域介绍，不能把整个市场当作一家餐厅凑数；核实到具体摊位后，才作为独立用餐候选。

不要把上述“按目的地调整”读成“只找到两家就可以停”。先做到地点库规范里的餐饮范围及逐餐窗覆盖，再按真实差异选择与取舍。预算要给带币种的每人/两人/每份口径及范围；未核实实时菜单价时可标有依据的编辑估算，“按菜单和当日份量”不是预算。点餐说明提供确实可点的菜式、口味与份量选择，不能每家都只写“各点主菜、甜点分食”。

每类用紧凑列表呈现。默认显示准确店名与一句“位置＋吃什么”，整行可点击展开；详情说明推荐理由、真实可点菜品、预算口径、用餐时段及必要的营业、店休、最后点单或预约条件，并提供地址、来源和导航。路线关联后置为短注，不能把每店介绍写成“第几天去”。用原生可键盘操作的折叠组件，手机不截断店名和摘要。已有分类推荐后，不再复制一块相同店名的地址表，地点库与当天候选引用同一地点。

菜单、价格和营业资料核对到准确分店；官网品牌首页或地图搜索不能证明某分店有某菜、某时段可用。受季节或服务时段限制的菜单注明适用范围；日期未知仍写常规限制与确认入口，不把用餐候选写成已订位。当天候选按实际区域、可用餐时段和路线角色选择，专程绕行的店说明代价，不因收录在餐饮章就自动进入当天推荐。

没有核实的价格用明确的编辑预算档位，不假装实时报价。Google 评分仅在易于核实准确分店时附上来源与查询日期，有条件再给评价量；拿不到就省略，不补猜测数字，也不为评分反复抓取。

折叠摘要、推荐理由与点餐详情分工不同：摘要帮助快速识别，why 解释这家与其他选择的差异，order 才展开具体菜式与吃法。不要把分类名当推荐理由，也不要把同一段完整点菜文字复制到摘要和详情。fit 说明这家实际适用的时段与位置条件，不批量写“按营业条件用于午餐或晚餐”；预算区分该候选实际承担的午餐/晚餐，不能用午餐套餐价代表晚餐。

交付前回看选题：读者是否看得到目的地的经典与当代特色，能否从菜式直接找到餐厅，主线是否给重要体验留下真实时间。不要用地点总数代替内容判断。

## 行前准备：三阶段的可完成任务

按行动时机组织三个阶段，通常为提前办理与预订、临近出发核对、出门前随身检查。阶段名称和时限服从目的地、真实日期与订单，不套固定“提前几天”的全球规则。每项说明适用于谁、要做什么、在哪个入口操作、怎样算完成；需要证件、预约或申报的任务保留对应官方入口与适用条件。笼统的“检查证件”“提前订票”不算完整任务。

出入境要求取决于国籍、旅行证件、居住或过境身份、行程与日期。用户未提供这些条件时，只能给需要确认的任务与查询方法，不能默认中国国籍、免签资格或必办某种签证。国内旅行、海岛、自然目的地按实际需要组织准备；不为了三阶段各自凑条目而加入无关申报、退税或预约。

同一任务的勾选标识在重排、分组和文字润色后保持稳定，完成状态不因数组位置变化串到另一任务；任务含义实质改变时按新任务处理，旧标识不能回收给无关事项。已完成只表示用户勾选，不代表系统核实了签证、订单或入场资格。清单、预约备注与离线联系信息继续保存在原浏览器数据中。

## 语言锦囊：按场景查词与沟通

先选实际场景，例如交通问路、住宿、点餐、购物、参观预约与求助；地名和日常标识可单独成组。进入后在同处切换会话、词语速查与常见回答，只有词汇的场景不制造空会话页。常用句约 4–5 句，词汇约 10–18 词，数量服从当地需要，不用近义问候凑数，也不沿用东京专用场景和词汇。

非英语目的地的每句、词语和回答都提供准确中文、当地表达及可独立使用的备用英语；罗马化读音不能代替翻译。英语目的地只提供中文与一套英语，不生成重复语种按钮、文本或填写字段。主卡可以直接出示，语言切换与场景切换相互独立。读音和使用条件按需展开，常见回答留在对应场景；读音采用该语言适用的方式，不把中文谐音当准确发音。常见回答注明意思和下一步可怎样回应，不把示例回答写成对方一定会说的话。涉及数字、时间、人数或物品的占位内容需能理解、能替换，避免把示例当成用户真实预订。

过敏、疾病、遗失证件等表达只写准确的沟通需求，不虚构用户状况或承诺服务结果；医学与入境判断仍回到实际资料与专业帮助。支持多种当地语言的旅程要注明适用地区或语言，不能仅靠城市名机械替换。

保留 GitHub 3.0 语言锦囊中的词汇用途：菜单、交通、购物等高频词与标识不能被完整句或常见回答替代。更新时保留已有词条，非英语目的地补齐英文，以 `languageScenes` 把同场景的三类内容关联起来，避免词典、句子、回答各自形成一长串重复分类。正文与旅行模式共用同一内容与输入状态。词表紧凑排列，控制组在窄屏仍可辨认；纸色、字体、细线与本刊一致，不把分类做成占满页面的大色块。字段见 [编写约定](authoring-contract.md)，交互见 [4.8 更新规范](update-4.8.md)。

## 时刻与地图

排时刻前必读 [营业与日历核对](opening-and-calendar.md)。主线、餐厅和备选都要核对当地日期/星期与可访问窗口；日期未知保留条件路线，不声称实际旅行日已确认。

- 每站时刻由每日数据驱动，正文与旅行模式共享。估算与预约时刻分开注明；不删时间以换取“杂志感”。上一站结束、转场和下一站开始不能相互重叠；保留午饭和实际移动空间。
- 雨天与疲劳备选用文字解释，不恢复已经取消的调整行程按钮。需要重新规划时，由用户提出后修改手册数据。
- 每一天有可理解的路线/街区图，另有全程总图。参考样刊第 2 天是含备选点的街区参考图，因此标注 A–E 并解释它不是当天完整导航线。新旅程要重新判断，不能照搬此特例。
- 坐标与底图投影必须对应，图上数字旁有可读地名，挤在一起时用引线和索引。实际道路方向、车站入口和列车换乘不从直线推断。

## 数据与隐私

旅行模式应有独立的「旅途笔记」入口，与当天行程、摄影参考、记账并列；票据与参考留在各地点内。区分全程共用的笔记与随日期切换的当天备注；杂志正文与旅行模式使用同一页面状态，输入即时互相更新，不另建一份记录。这不是多人共享、跨标签页同步或云同步。编辑时不重建输入框，避免打断中文输入和光标；切换日期、工具和关闭后重开均保留内容，并显示真实的本机保存状态。手机单列显示，输入字号至少 16px。

保留当前浏览器的笔记、收藏、清单、成员、账目和附件。旧手册修复不改存储键；新城市或新旅程隔离存储键。附件通过 IndexedDB 保存，本机数据不等于云端共享。浏览器换源、换端口或清理数据可能改变记录可见性，使用已有导出导入功能迁移。

## 文风

交付页面不出现本地测试、样刊、模板复用、制作过程、字体清单或核验工作日志等面向制作者的说明。内部研究记录留在工作文件中，不渲染给读者。事实来源在对应正文旁紧凑显示，必要时另设可展开总表；不能只放全书末尾，逐图署名继续保留。建议时间、未确定的航班住宿、本机保存范围等会影响实际使用的信息，放在对应功能处，用面向旅行者的话说明。

用具体地点、空间、食物与观看线索写介绍，需要执行时再写动作、时间与取舍，不要求每段回到当天安排。少用“邂逅”“解锁”“沉浸”“治愈之旅”等泛化宣传。英文大字是视觉层，章节用途必须有清楚的中文说明。城市背景可以慢读；地址、时间和操作保持短而明确。通读方法见 [旅行编辑语言](travel-editorial-voice.md)。

穷游锦囊提供内容组织的启发，不是事实核验的替代品。历史 PDF 的开放时间、价格、交通、门店与规则不得当成当前资料。

## 区域与特色体验的边界

本章以真实区域差异为主线，大图后显示完整区域正文，各街区分小节；体验可作为“细看一处”整合其中，避免另写一轮相同路线摘要。区域介绍具体地理、产业、生活方式、街道与观看线索，末尾只保留相关日程入口。跨区移动与上午下午的次序放每日行程。城市按街区，海岛按海岸与聚落，多城旅行按城市或片区组织；选题和篇幅按当地事实与读者兴趣决定。

缺图不是空白图片卡的理由。先快速寻找能核对地点或分店的图片；找不到合适的就用紧凑文字卡，移除图片格与行程图片列。品牌图、餐品图、区域图明确标注角色，不能冒充门店实景；低分辨率图只用于小图，不升级为精选大卡。发布前检查所有地点的配图状态，而非只看总图片数。
