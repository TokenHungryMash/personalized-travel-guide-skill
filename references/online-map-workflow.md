# Interactive maps and bounded verification

This is the interactive-map route. For phone/offline screenshot delivery, use screenshot-map-workflow.md: the same real map source is rendered large on an authorized desktop browser and embedded as reviewed still images. Do not require the phone to load this runtime for screenshot maps.

Interactive current-system builds use MapLibre GL JS 5.6.0 with OpenFreeMap Liberty: https://tiles.openfreemap.org/styles/liberty . No registration or API key is required. See https://openfreemap.org/quick_start/ . The adapter emits scripts/online-route-map.js as trip-route-maps.js. The browser loads the library and basemap only when the map tab is rendered. Keep attribution. Plot the selected day's existing verified coordinates in itinerary order; label connecting lines as itinerary links, not routed navigation. The numbered route list is always available offline. Missing network/WebGL must not hide that list or block handbook generation.

Do not run prepare_osm_route_tiles.py or build_system_routes.cjs for ordinary new builds. Those are legacy offline-map utilities, used only when offline real basemaps are explicitly requested. Exact snapshot restoration remains unchanged. Online builds have no required media/routes/day-N.svg artifacts; retain runtime-binding, syntax, coordinate and fallback checks. Never claim live map rendering from static checks alone.

## Verify once using available tools

Nearby marker buttons are grouped at the current screen scale without modifying stop coordinates. A grouped button shows the stop count; its accessible label and popup list all original numbers and names. Zooming separates nearby stops; exactly coincident stops remain grouped. Verify stop coverage using the popup/list, not by requiring the number of marker buttons to equal the number of stops. Visible zoom controls supplement dragging and wheel/touch gestures.

- Inventory the available browser tool and runtime once. Do not assert agent-browser or playwright-cli is installed. Prefer an already available supported browser; reuse an existing Playwright setup if authorized and available. Do not cycle through unavailable CLIs or repeatedly install dependencies for screenshots. Respect host access denials.
- Use a fixed-height, positioned map container. On blank output, first inspect container and canvas dimensions, visibility, and parent layout; then page errors, network failures, style/source events; investigate WebGL/worker or dependency versions only with supporting evidence.
- Use real event waits with a bounded timeout, not virtual-time flags. Run one desktop and one narrow-viewport sample: actual basemap pixels, Chinese names, markers/line, attribution, pan/zoom, day switch and offline fallback. A headless narrow viewport is not a physical-phone test.
- 5.6.0 is the tested baseline, not proof that v4 caused a previous blank screen. Do not enable preserveDrawingBuffer or SwiftShader in production merely because a screenshot was blank. Retain non-blocking warnings in diagnostics; do not globally suppress errors or restart the entire test for favicon 404. Investigate repeat ResizeObserver errors if resizing is affected.
- Aim for 3–5 minutes for repeat map integration and checking in an already prepared environment; this is a target, not a promised SLA or reason to fabricate a pass. After two failed attempts at the same operation, record the concrete failure and keep the usable route-list fallback. Stop map-specific environment work at the time budget and continue other handbook work; preserve unobserved checks as pending.
- Windows: use PowerShell-compatible commands, explicit UTF-8 for files, and avoid assuming PS 7 operators on PS 5.1. A loopback preview URL is local-machine only; physical-phone LAN testing requires an appropriately bound server and reachable host address.

Record elapsed integration, browser validation, network load and environment setup separately. Measure each run; tile-ready time is not whole-build duration or a universal network promise.

Map markers show original stop number plus a short place name by default, not bare numbers. Cluster labels show the stop count and first actual place name with 等, never an invented district label. Full names and original numbers remain in the popup, accessible label and list. Collision grouping accounts for the 136px name pills; the map fit reserves horizontal space for labels. Recheck representative mobile/desktop layout after label changes; previous numeric-marker screenshots are not verification of name labels.
